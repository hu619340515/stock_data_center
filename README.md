# 高性能 A股量化数据下载器 (DuckDB版)

这是一个基于 Python 的高性能 A股历史行情数据下载工具。它利用 **Baostock** 作为数据源，**DuckDB** 作为存储引擎，实现了**多进程并发下载**、**断点续传**和**批量高速写入**。

## 核心特性

- **多进程并发**：利用多核 CPU 优势，开启多个进程同时下载，速度是单线程的数倍。
- **DuckDB 极速存储**：使用列式存储数据库 DuckDB，配合批量写入优化，写入速度极快。
- ️ **断点续传**：自动检测数据库中已有的股票数据，跳过已下载部分，支持任务中断后继续运行。
- **实时进度监控**：每个进程独立汇报下载进度，主进程汇报入库进度，拒绝“假死”。
- **增量更新**：支持每日增量更新，自动计算最后更新日期，只下载最新数据。

## 快速开始

### 1. 配置参数

编辑 `config.py` 可以根据需要调整设置：

```
# 数据库文件路径
DATABASE_PATH = "quant_data.db"

# 并发进程数 (建议 3-5，过高可能导致 IP 被封)
MAX_WORKERS = 3

# 全量下载起始日期
START_DATE_FULL = "1999-01-01"
```

### 2. 命令行操作

项目提供了简单的命令行工具 `cli.py`。

#### 全量下载 (首次运行)

下载所有 A股股票的历史数据。支持断点续传，如果中途停止，再次运行会自动跳过已下载的股票。

```
python cli.py full
```

#### 增量更新 (每日运行)

自动检测每只股票在数据库中的最后更新日期，并下载之后的新数据。

```
python cli.py update
```

#### 查看状态

查看当前数据库中的股票数量和记录总数。

```
python cli.py status
```

## 核心逻辑说明

### 多进程架构

为了解决 Python GIL 锁和 I/O 阻塞问题，采用了 **多进程 + 队列** 的架构：

1. **主进程**：负责任务分发、接收数据队列、批量写入数据库。
2. **子进程**：仅负责调用 Baostock 接口下载数据，不直接操作数据库（避免文件锁冲突）。

### 批量写入优化

为了提升 DuckDB 的写入性能，程序不会每下载一只股票就写入一次磁盘，而是先在内存中维护一个缓冲区 (`batch_buffer`)。

- 当缓冲区积攒到一定数量（如 50 只股票）时，触发一次 `INSERT` 操作。
- 这比单条写入快几十倍。

### 数据安全

- **VACUUM 机制**：下载完成后会自动执行 `FORCE CHECKPOINT`，优化数据库文件体积。
- **异常处理**：每个进程都有独立的异常捕获，单个股票下载失败不会导致整个程序崩溃。

## ️ 注意事项

1. **Baostock 限制**：Baostock 对单 IP 的并发请求有限制，建议 `MAX_WORKERS` 不要设置超过 **5**。如果遇到连接超时，请减少进程数。
2. **数据库锁定**：请勿在下载过程中手动用其他工具打开 `quant_data.db` 文件，否则会导致 `Database is locked` 错误。
3. **Windows 兼容性**：在 Windows 上运行时，必须保证入口代码在 `if __name__ == '__main__':` 块中（`cli.py` 已处理好）。

## 常见问题

**Q: 为什么屏幕日志有时候会停顿几秒？**
A: 这是正常现象。为了减少刷屏，子进程设置为每下载 10 只股票才打印一次日志。停顿期间，程序正在后台高速处理数据。

**Q: 遇到 **`INTERNAL Error`** 怎么办？**
A: 这通常是 DuckDB 的偶发性错误。程序已内置了自动重试机制。如果彻底卡死，建议删除 `.db` 文件重新开始（或者升级 DuckDB 版本）。

**Q: 数据保存在哪里？**
A: 默认保存在项目根目录下的 `quant_data.db` 文件中。你可以使用 DuckDB CLI 或 Python 脚本读取分析。
