# 高性能 A股量化数据下载器 (DuckDB版)

这是一个基于 Python 的高性能 A股历史行情数据下载工具，同时内置了一个**可视化 Web Viewer**。它利用 **Baostock / AKShare** 作为数据源，**DuckDB** 作为存储引擎，实现了**多进程并发下载**、**断点续传**、**批量高速写入**、**动态并发控制**和**多时间粒度支持**，并提供浏览器可视化界面方便查询与管理。

## 核心特性

- **多数据源支持**：内置Baostock和AKShare双数据源支持，覆盖不同使用场景需求
- **自动故障切换**：主数据源故障时自动按优先级切换到备用数据源，无需人工干预，保证下载任务不中断
- **多进程并发**：利用多核 CPU 优势，开启多个进程同时下载，速度是单线程的数倍
- **动态并发控制**：根据错误率和成功率自动调整进程数，平衡下载速度与API限制
- **动态批处理**：基于内存使用率自动调整批处理大小，优化写入性能
- **DuckDB 极速存储**：使用列式存储数据库 DuckDB，配合批量写入优化，写入速度极快
- **断点续传增强**：自动检测数据库中已有的股票数据，支持按日期范围断点续传，智能补全缺失数据
- **指数退避重试**：网络错误时自动重试，延迟时间指数增长并加入随机抖动，提高成功率
- **多时间粒度支持**：支持日线、周线、月线等不同时间粒度数据存储与查询
- **全量ETF支持**：覆盖全市场1400+只ETF基金，支持51/56/58/15/159所有号段
- **数据导出功能**：支持将数据导出为CSV、Parquet、JSON等格式
- **数据源抽象接口**：定义统一数据源接口，支持多数据源切换和故障自动切换
- **实时进度监控**：显示处理进度、速度统计、剩余时间和成功率等关键指标
- **配置管理优化**：使用YAML配置文件集中管理参数，支持环境变量替换
- **多进程增量更新**：增量更新也采用多进程方式，与全量下载一样高效，速度可达26+只/秒
- **Web 可视化 Viewer**：内置 Flask 服务，提供浏览器界面，支持数据浏览、K线图表、趋势分析、数据管理与一键数据更新

## 快速开始

### 1. 配置参数

编辑 `config.yaml` 可以根据需要调整设置，每个配置项都有详细的中文说明：

```yaml
# 数据库配置
database:
  path: "quant_data.db"  # 数据库文件路径，默认保存在项目根目录下，支持相对路径和绝对路径

# Baostock 配置
baostock:
  adjust_flag: "2"  # 复权类型：1-后复权，2-前复权，3-不复权，建议使用前复权(2)以保持价格连续性

# 并发与性能配置
concurrency:
  max_workers: 4  # 最大并发进程数，建议3-5，过高可能导致IP被封或网络拥堵
  dynamic_concurrency: true  # 是否启用动态并发控制，true表示根据错误率和成功率自动调整进程数
  min_workers: 2  # 最小并发进程数，当错误率过高时会减少到此值
  max_workers_limit: 5  # 最大并发进程数限制，动态调整时不会超过此值
  error_threshold: 3  # 错误率阈值(%)，当错误率超过此值时自动减少进程数
  success_threshold: 95  # 成功率阈值(%)，当成功率超过此值时自动增加进程数

# 批量写入优化
batch:
  size: 50  # 初始批处理大小，每积累50只股票的数据后批量写入数据库
  max_size: 200  # 最大批处理大小，动态调整时不会超过此值
  min_size: 20  # 最小批处理大小，动态调整时不会低于此值
  memory_threshold: 0.8  # 内存使用率阈值(0-1)，当内存使用率超过80%时自动减少批处理大小

# 重试机制配置
retry:
  max_retries: 3  # 最大重试次数，网络错误时会自动重试此次数
  initial_retry_delay: 1  # 初始重试延迟时间(秒)，第一次重试等待1秒
  max_retry_delay: 30  # 最大重试延迟时间(秒)，重试延迟不会超过此值
  retry_backoff_factor: 2  # 重试退避因子，每次重试延迟时间乘以此因子(1秒、2秒、4秒...)

# 数据源配置
datasource:
  default: "baostock"  # 默认数据源，支持 baostock / akshare
  enable_fallback: true  # 是否启用数据源故障切换，true表示当主数据源失败时自动切换到备用数据源
  priority: ["baostock", "akshare"]  # 数据源优先级列表，按顺序尝试，自动故障切换

## 数据源对比
| 特性 | Baostock | AKShare |
|------|----------|---------|
| 股票数量 | ~5000只 | ~5300只（更全） |
| ETF数量 | ~900只 | ~1400只（全覆盖所有号段） |
| 登录要求 | 需要登录，会话可能过期 | 无需登录 |

| 数据更新 | T+1盘后较晚 | T+1盘后更新更快 |
| 调用限制 | 有并发限制 | 无明确限制 |
| 推荐场景 | 历史数据批量下载 | 日常增量更新、ETF数据下载

# 数据范围配置
data:
  start_date_full: "1999-01-01"  # 全量下载的起始日期，首次运行时从此日期开始下载
  start_date_incremental: "2024-01-01"  # 增量更新的起始日期，用于每日更新任务

# 错误处理配置
error:
  log_file: "error_log.txt"  # 错误日志文件路径，记录所有下载失败的股票和错误信息
  max_errors_before_warning: 10  # 累计错误数警告阈值，每累计10个错误时在控制台显示警告信息

# 数据处理配置
processing:
  use_arrow: false  # 是否使用Apache Arrow格式处理数据，true可提升大数据量的处理性能但需要额外依赖
  compress_data: true  # 是否压缩数据，true表示在传输和存储时压缩数据以节省带宽和磁盘空间
```

### 2. 命令行操作

项目提供了完整的命令行工具 `cli.py`。

#### 全量下载 (首次运行)

下载所有 A股股票的历史数据。支持断点续传，如果中途停止，再次运行会自动跳过已下载的股票。

```bash
python cli.py full
```

#### 增量更新 (每日运行)

自动检测每只股票在数据库中的最后更新日期，并下载之后的新数据。

```bash
python cli.py update
```

#### 数据导出

将数据库中的数据导出为指定格式：

```bash
# 导出单只股票数据
python cli.py export --code sh.600000 --start-date 2024-01-01 --end-date 2024-12-31 --output output.csv

# 导出所有股票数据
python cli.py export --start-date 2024-01-01 --end-date 2024-12-31 --output all_data.csv

# 指定数据频率和格式
python cli.py export --code sh.600000 --start-date 2024-01-01 --end-date 2024-12-31 --output weekly.parquet --frequency w --format parquet
```

支持的频率：
- `d`：日线（默认）
- `w`：周线
- `m`：月线

支持的格式：
- `csv`：CSV格式（默认）
- `parquet`：Parquet格式
- `json`：JSON格式

#### 查看状态

查看当前数据库中的股票数量和记录总数。

```bash
python cli.py status
```

## 核心逻辑说明

### 多进程架构

为了解决 Python GIL 锁和 I/O 阻塞问题，采用了 **多进程 + 队列** 的架构：

1. **主进程**：负责任务分发、接收数据队列、批量写入数据库、动态并发控制
2. **子进程**：仅负责调用 Baostock 接口下载数据，不直接操作数据库（避免文件锁冲突）

**重要设计决策**：
- **数据库独占访问**：只有主进程访问数据库文件，完全避免了多进程同时访问导致的文件锁定问题
- **自动去重机制**：数据库表使用 PRIMARY KEY (code, date)，通过 INSERT OR REPLACE 自动处理重复数据
- **简化子进程逻辑**：子进程直接下载完整日期范围的数据，不需要查询数据库判断是否已下载
- **主进程智能处理**：主进程负责数据去重和批量写入，确保数据一致性

### 动态并发控制

系统实现了智能的并发控制机制：

- **错误率监控**：实时监控下载错误率，当错误率超过阈值时自动减少进程数
- **成功率监控**：当成功率稳定时，逐步增加进程数以提高下载速度
- **进程数限制**：进程数在 `min_workers` 和 `max_workers_limit` 之间动态调整

### 批量写入优化

为了提升 DuckDB 的写入性能，程序不会每下载一只股票就写入一次磁盘，而是先在内存中维护一个缓冲区 (`batch_buffer`)。

- 当缓冲区积攒到一定数量（默认50只股票）时，触发一次 `INSERT` 操作
- 对于大型数据（超过1000条记录），使用 `COPY` 命令进行更高效的批量导入
- 动态批处理：根据内存使用率自动调整批处理大小，避免内存溢出

### 断点续传增强

系统支持智能的断点续传机制：

- **自动去重**：利用数据库的 PRIMARY KEY (code, date) 自动去重，重复数据会被替换
- **增量更新**：每次运行时下载完整日期范围，数据库自动过滤已存在的数据
- **进度保存**：实时保存下载进度，即使程序异常退出也能恢复
- **高效处理**：不需要预先查询数据库判断哪些数据缺失，简化了逻辑，提高了效率

### 指数退避重试

网络错误时自动重试，采用指数退避算法：

- 延迟时间指数增长：1秒、2秒、4秒...
- 加入随机抖动：避免多个进程同时重试造成雷群效应
- 最大重试次数：默认3次，可通过配置文件调整

### 多时间粒度支持

系统支持不同时间粒度的数据存储：

- **日线数据**：存储在 `stock_daily` 表
- **周线数据**：存储在 `stock_weekly` 表
- **月线数据**：存储在 `stock_monthly` 表
- 每个表都有独立的索引和查询优化

### 数据源抽象接口

系统定义了统一的数据源接口：

- **DataSourceInterface**：定义了数据源的统一接口
- **多数据源支持**：可以轻松添加新的数据源（如Tushare、AKShare等）
- **故障自动切换**：当一个数据源失败时，自动切换到备用数据源

### 实时进度监控

系统提供详细的进度监控：

- **处理进度**：显示已处理的股票数量和总数量
- **速度统计**：显示当前下载速度（股票/秒）
- **剩余时间**：估算剩余完成时间
- **成功率**：显示成功率和错误数

### 多进程增量更新

系统采用与全量下载相同的多进程架构实现增量更新：

1. **主进程**：
   - 计算每只股票的最后更新日期
   - 生成每只股票的更新日期范围
   - 切分任务并分发给子进程
   - 接收数据队列并批量写入数据库
   - 动态调整并发数和批处理大小

2. **子进程**：
   - 接收股票列表和日期范围
   - 下载指定日期范围内的数据
   - 将下载的数据放入队列
   - 不直接访问数据库，避免文件锁定

**性能表现**：
- 平均速度：26+ 只/秒
- 处理时间：5482 只股票仅需约 3.5 分钟
- 成功率：100% 成功率
- 稳定性：完全避免数据库锁定错误

**智能日期计算**：
- 自动检测每只股票的最后更新日期
- 根据当前时间智能调整结束日期（避免获取未更新的数据）
- 确保只下载真正需要更新的数据

### 数据安全

- **VACUUM 机制**：下载完成后会自动执行 `FORCE CHECKPOINT`，优化数据库文件体积
- **异常处理**：每个进程都有独立的异常捕获，单个股票下载失败不会导致整个程序崩溃
- **数据验证**：下载的数据会进行基本的验证，确保数据完整性

## 注意事项

1. **Baostock 限制**：Baostock 对单 IP 的并发请求有限制，建议 `max_workers` 不要设置超过 **5**。如果遇到连接超时，请减少进程数
2. **数据库锁定**：请勿在下载过程中手动用其他工具打开数据库文件，否则会导致 `Database is locked` 错误
3. **Windows 兼容性**：在 Windows 上运行时，必须保证入口代码在 `if __name__ == '__main__':` 块中（`cli.py` 已处理好）
4. **内存使用**：动态批处理会根据内存使用率自动调整批处理大小，如果系统内存不足，可以减小 `batch_size`
5. **网络稳定性**：指数退避重试机制可以处理网络波动，但网络不稳定时建议降低并发数
6. **数据完整性**：系统会自动检测和补全缺失数据，但建议定期运行 `update` 命令保持数据最新
7. **配置文件**：修改 `config.yaml` 后无需重启程序，下次运行时会自动加载新配置
8. **环境变量**：支持在配置文件中使用环境变量，格式为 `${ENV_VAR_NAME}`

## 常见问题

**Q: 为什么屏幕日志有时候会停顿几秒？**
A: 这是正常现象。为了减少刷屏，子进程设置为每下载一定数量的股票才打印一次日志。停顿期间，程序正在后台高速处理数据。

**Q: 遇到 `INTERNAL Error` 怎么办？**
A: 这通常是 DuckDB 的偶发性错误。程序已内置了自动重试机制。如果彻底卡死，建议删除数据库文件重新开始（或者升级 DuckDB 版本）。

**Q: 遇到 "另一个程序正在使用此文件" 错误怎么办？**
A: 这个错误已经被修复。系统现在采用数据库独占访问模式，只有主进程访问数据库文件，完全避免了多进程同时访问导致的文件锁定问题。如果您仍然遇到此错误，请确保：
- 没有其他程序（如数据库管理工具）正在打开数据库文件
- 没有多个下载进程同时运行
- 数据库文件没有被其他进程锁定

**Q: 数据保存在哪里？**
A: 默认保存在项目根目录下的 `quant_data.db` 文件中。你可以使用 DuckDB CLI 或 Python 脚本读取分析。

**Q: 如何导出数据？**
A: 使用 `export` 命令可以将数据导出为 CSV、Parquet 或 JSON 格式。支持按股票代码、日期范围、时间粒度进行筛选导出。

**Q: 如何添加新的数据源？**
A: 实现 `DataSourceInterface` 接口，并在 `config.yaml` 中配置数据源。系统会自动进行故障切换。

**Q: 动态并发控制是如何工作的？**
A: 系统会实时监控错误率和成功率。当错误率超过阈值时，自动减少进程数；当成功率稳定时，逐步增加进程数。进程数在 `min_workers` 和 `max_workers_limit` 之间动态调整。

**Q: 如何查看下载进度？**
A: 系统会实时显示处理进度、速度统计、剩余时间和成功率。默认每处理10只股票显示一次进度，可通过配置文件调整。

**Q: 断点续传是如何实现的？**
A: 系统采用自动去重机制。每次运行时下载完整日期范围的数据，数据库利用 PRIMARY KEY (code, date) 自动过滤重复数据。这种方式简化了逻辑，避免了多进程访问数据库导致的文件锁定问题，同时确保了数据的一致性。

**Q: 如何优化下载速度？**
A: 可以通过以下方式优化：
- 调整 `max_workers` 参数增加并发数（建议不超过5）
- 启用 `dynamic_concurrency` 让系统自动调整并发数
- 启用 `dynamic_batch_size` 让系统自动调整批处理大小
- 确保网络稳定，避免频繁重试

**Q: 测试失败怎么办？**
A: 运行 `python test/run_tests.py` 查看详细的测试报告。如果测试失败，请检查：
- 依赖库是否正确安装
- 网络连接是否正常
- 配置文件是否正确
- 数据库文件是否被锁定
